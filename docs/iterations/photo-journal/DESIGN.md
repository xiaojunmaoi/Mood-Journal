# 心晴 v1.1 设计提案：照片手帐

日期：2026-09-27。状态：早期设计探索存档。以下前三张图和混合轻记录方案已被后续选择替代。

**最终选定方案**：[独立生活影集](04-selected-album.png) + [独立写作页](05-selected-editor.png)。首页仅提供入口，照片添加与阅读展示分开。实际 v1.1 规则、实现范围及验收以 [照片手帐 PRD](../../PHOTO-JOURNAL.md) 为准。

## 1. 这次迭代解决什么

用户平时拍生活照片，旅行时拍风景，想在照片旁留下一句话，也可能写一篇完整日记。心晴用同一条记录保存照片、文字、日期和可选心情，让「拍下了什么」与「当时的感受」一起留存。

本版产品目标：从照片开始也能轻松记录，想多写时有安静的完整编辑页，过后能按日期读回照片与文字。

本方案把用户所说的「同步记录」理解为照片和文字一起记录。第一版建议仍为本地保存；网页与 App 跨端同步应作为后续独立能力，不能把「草稿已保存」表述为「云端已同步」。

## 3. 用户路径

### 日常随拍

首页「添加照片」 → 选择照片 → 写一句话（可跳过） → 可选心情 → 「存下这一刻」 → 在我的手帐看到刚保存的图文记录。

### 旅行日记

首页「展开写日记」或手帐「记一笔」 → 选择照片 → 调整记录日期 → 可选标题 → 写正文 → 可选心情 → 保存 → 阅读详情。

从轻记录进入完整编辑器时，原有照片、顺序、心情、标签与文字全部带入，保持同一份草稿，不生成两篇重复日记。

### 回看与修改

情绪回顾 → 我的手帐 → 按日期浏览 / 筛选有照片 → 打开记录 → 查看完整文字、左右滑动照片 → 按需编辑或删除。

## 4. 信息架构

保持现有三项主导航：今日心情 / 情绪回顾 / 自我关怀。

- 今日心情：保留快捷情绪记录；增加照片、可编辑日期和完整编辑入口。
- 情绪回顾：增加「情绪趋势 / 我的手帐」二级切换；既有趋势与因素统计保留在趋势视图，全部历史记录统一放在手帐。
- 自我关怀：沿用既有呼吸、自然声、散步及反馈。
- 完整日记编辑器：独立专注页面，手机使用全屏；回到首页可继续同一份草稿。
- 日记详情：完整照片组 + 标题（若有）+ 正文 + 可选心情与标签 + 更多操作。

不新增需要用户分别维护的「相册记录」与「情绪记录」两份数据。

## 5. 第一版功能规则

| 功能 | 建议规则 |
|---|---|
| 添加照片 | 每条 0～9 张。安卓使用系统照片选择入口，并提供主动拍照入口；桌面使用文件选择。权限取消后保留文字草稿。 |
| 照片整理 | 支持预览、移除、调整顺序；首张作为列表封面。手机长按排序，并提供「设为封面 / 前移 / 后移」作为不依赖拖动的操作。 |
| 原图处理 | 保存供手帐使用的副本；不改变、不删除用户相册原图。缩略图可裁切展示，详情允许查看完整比例。 |
| 轻文字 | 默认维持短输入区，写一句即可；「展开写日记」进入完整编辑器。 |
| 长日记 | 正文统一最多 5,000 字，支持自然换行与段落。短输入区的 500 字是快捷编辑边界，到达时引导展开，不截断已有内容。 |
| 标题 | 选填，最多 40 字；无标题时列表显示正文摘要，纯照片时显示日期，不生成夸张的 AI 标题。 |
| 记录日期 | 默认今天，允许补记过去日期，不允许未来日期；首版不自动根据照片推断日期或地理位置。 |
| 心情与标签 | 心情和影响因素均可选。有照片、有非空正文、或选择了心情，任一满足即可保存；仅标题、日期或标签不能保存为空记录。 |
| 草稿 | 自动保存到本机；明确显示保存中 / 已保存 / 保存失败。只有照片与文字都持久化成功才显示已保存。重开后可继续或丢弃。 |
| 浏览 | 倒序日期分组，同日多条分别展示。列表支持「全部记录 / 有照片」，每条展示封面、照片张数、文字摘要与可选心情。 |
| 编辑删除 | 可修改照片、顺序、日期和文字；保存更新原记录，不另增一条。删除整篇前确认。照片移除只影响手帐副本。 |
| 本地备份 | 正式承载照片前提供包含文字和照片的完整导出 / 恢复路径；不是只导出图片路径。恢复先预览记录数，默认按记录 ID 跳过已有记录；同 ID 内容不同时提示，不静默覆盖。 |

首版暂不加入视频、社交发布、自动定位、自由贴纸排版、富文本图文混排、AI 自动分析照片或自动生成游记。后续根据实际使用再扩展。

## 6. 与原有情绪功能如何共存

- 原有只选心情、不写文字的记录仍可保存。
- 有照片但未选心情的日记出现在手帐中，不参与情绪均值或低落因素统计，也不自动记为「一般」。
- 有心情的图文日记按其记录日期参与原有统计；无记录日仍为空白。
- 补记或修改日期后，相关日期的统计重新计算。
- 影响因素保留原来的语义。首版不把「旅行」或照片内容自动识别为触发因素，不从图片判断情绪。
- 已有历史记录迁移为无照片、无标题的记录，正文、心情、标签、ID 和日期都保留。
- 示例模式仍与个人手帐隔离，照片与文字均不得混入个人数据。

## 7. 重要交互与异常状态

| 状态 | 页面反馈与处理 |
|---|---|
| 未添加照片 | 一个轻量「添加照片」入口，不用大块灰底占据纸张背景；无照片也能完成原有记录。 |
| 添加与处理照片 | 逐张显示进度；处理未完成时不能把整篇标为已保存。允许取消单张。 |
| 超过 9 张 | 显示可用剩余数量；保留已选，不静默丢掉超限照片。 |
| 格式不支持或图片损坏 | 指出失败的那张，提供重新选择 / 移除；保留其他内容。支持格式按网页和 Android 的实际验证结果说明，不空泛承诺全部格式。 |
| 文字过长 | 接近上限提示；粘贴超限时保留输入并明确提示调整，不静默截断。 |
| 草稿保存失败 | 不显示「草稿已保存」；保留当前内容，支持重试，离开前提醒。 |
| 本地空间不足 | 明确失败原因，保留尚可恢复的草稿；提供重试 / 先移除部分照片。不得自动删除旧日记腾空间。 |
| 点击返回或系统返回键 | 已可靠保存草稿可直接返回；未保存成功时让用户选择继续编辑、重试保存或放弃。 |
| 编辑已保存日记 | 修改先进入编辑草稿；取消编辑不覆盖原记录。 |
| 手帐为空 | 文案「有些日子，一张照片就能记住。」+「记录第一张照片」，与纸纹背景融为一体。 |
| 详情照片加载失败 | 保留文字及照片位置，提供重试；不把日记变成空记录。 |

## 8. 手机端设计重点

- 首页继续承担轻记录；照片从 3 列缩略图开始，最多 3 行，长正文在独立页面编辑。
- 编辑器采用单列：日期 → 可选标题 → 照片组 → 正文 → 可选心情。
- 编辑已有长日记时直接进入完整编辑器，不退回 500 字快捷输入框。
- 键盘展开后，保存操作保持可达，输入光标不被工具条遮挡；在真实安卓手机验证键盘、系统返回和照片选择。
- 照片点击放大、左右切换，显示当前张数；退出预览回到原滚动位置。
- 同一篇中照片的顺序、封面、预览页码始终一致。
- 按钮和照片操作提供足够触摸面积；长按拖动不是唯一排序方式。
- 温暖质感主要由纸色、文字和少量植物细节提供，不给每张照片添加复杂装饰，不让大面积花卉抢走内容。

## 9. 数据与隐私边界

该迭代的照片数量会明显增加本地数据量。实施时应为照片安排独立文件 / 二进制存储，不把所有原图直接堆进现有文字存储。具体压缩与存储策略需要在真实设备上验证后定案。

- 元数据建议增加可选标题、有序照片引用、记录日期、创建 / 修改时间；心情允许为空。
- 日期使用用户选择的当地日期，创建时间另存，避免补记和时区改变导致错误分组。
- 保存流程先确保图片副本可用，再提交完整记录；失败时不丢旧版本、不留下可见的半篇记录。
- 编辑移除的照片在新记录可靠保存后再清理；取消编辑不得提前删除旧照片。
- 数据默认保存在当前设备，本版不承诺跨端自动同步、应用锁或端到端加密。
- 「仅自己可见」表示不会公开发布，不表示手机解锁后的其他使用者无法打开，也不应以锁图标暗示已有应用密码。
- 导出备份应包含照片和文字；备份文件由用户自行保管。卸载 App / 清理应用数据可能丢失本机记录。
- 不默认读取照片地理位置信息，不默认上传照片给 AI 或云端。

## 10. 实施顺序与验收

建议按一个完整闭环交付：记录模型兼容旧数据 → 图文及草稿持久化 → 手机完整编辑器与照片选择 → 首页快捷入口 → 手帐列表与详情 → 备份恢复 → 真实手机验收。

关键验收：

1. 原有仅情绪、短文字记录升级后完整可读，原有回顾与关怀功能可继续使用。
2. 纯照片、纯文字、照片加长文、仅心情四种记录均能保存和重开查看。
3. 1 张 / 9 张、横图 / 竖图都能完整预览，超限有明确提示。
4. 调整顺序后列表封面、详情顺序、预览页码同步改变。
5. 从快捷输入进入长文，或返回继续写，文字和照片均不丢失、不重复提交。
6. 补记过去日期后归档正确，未选心情的照片记录不会改变情绪均值。
7. 中途切后台、重启 App、拒绝照片权限、存储写入失败时不伪报成功。
8. 导出后在隔离的空环境恢复，照片、正文、日期、顺序和心情一致，重复导入不重复添加。
9. 在真实安卓手机完成系统相册选择、拍照取消、键盘遮挡、系统返回、离线查看等流程验证。

上述是本次设计建议与后续验收标准，不是对当前 APK 已有能力的声明。
