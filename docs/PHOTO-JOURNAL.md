## 1. 需求与目标

用户拍下日常生活或旅行风景后，希望同时留下一句话，或者整理成较长的日记。照片与文字应共同保存，回看时保留像翻相册一样的阅读感。

目标：一份记录支持照片、文字和可选心情；浏览和添加分开；保留既有快速情绪记录与关怀功能。这里的「同步记录」指图文一起记录，当前不包含自动云同步。

用户故事：

- 随手拍了一杯咖啡，选一张照片、写一句话即可保存。
- 旅行结束后选多张照片，安排封面和顺序，补记旅行当天并写长文。
- 回看时先看到照片与文字，点击才读全文，不被上传框或编辑控件打扰。
- 换设备前导出日记，在另一端预览备份后手动恢复。

## 2. 信息架构与入口

```text
今日心情 #today
  ├─ 原有五档心情 + 标签 + 500 字快捷记录
  └─ 用照片和长日记，留住生活 → #write
情绪回顾
  ├─ 情绪趋势 #review
  └─ 我的手帐 #album
       ├─ 只读影集：全部记录 / 有照片
       ├─ 记一笔 → #write
       ├─ 备份与恢复
       └─ 记录卡片 → #entry/:id
            ├─ 只读正文、照片大图、心情、标签
            └─ 更多 → 编辑 #edit/:id / 确认删除
```

编辑器独立占满当前内容区域，隐藏站点导航、日期侧栏与页脚，顶部只有取消、标题、保存。取消会离开编辑页并保留已成功写入的草稿；「丢弃草稿」二次确认后才删除。保存成功进入该篇阅读详情。

## 4. 字段与校验

| 字段 | 规则 | 空值处理 |
|---|---|---|
| 标题 | 可选，最多 40 个 JS 字符 | 展示时取正文首行摘要，否则「留住这一刻」 |
| 正文 | 可选，最多 5,000 个 JS 字符，保存前 trim | 允许纯照片或只选心情；HTML 作为纯文本 |
| 照片 | 可选，最多 9 张，顺序保留 | 第一张是主图；1 张大图、2 张并排、3 张及以上显示前三张拼贴与总数；无图记录独占一行 |
| 记录日期 | 默认今天，可选择过去日期，不可未来日期 | 存储为本地 YYYY-MM-DD，不随展示时区改变 |
| 心情 | 可选，1–5，或 null | 未填写不推断，不进入趋势平均值 |
| 影响因素 | 可选，沿用七类标签，多选去重 | 不根据文字/照片自动补标签 |

至少要有心情、非空正文、照片三者之一。仅标题或标签不能保存。过长正文不静默截断，显示错误并保留输入。保存期间禁用重复提交，写入失败不跳转、不虚构保存成功。

标题与正文使用 `textContent` / 表单 value 展示，不执行输入中的脚本。

## 5. 照片流程

1. 「添加照片」打开文件选择器；「拍一张」请求设备相机/相应选择器。桌面端可能仍显示文件选择，取决于平台。
2. 每张最多 20 MB、5,000 万像素；主要支持 JPEG、PNG、WebP。HEIC/HEIF 只有平台能解码时才可用，不支持时提示换格式。
3. 本地解码后复制为 JPEG，最长边不超过 1,800px、质量参数 0.84；透明区域铺白；不保留原始 EXIF 等元数据。
4. 处理的是应用中的副本，不改动相册原图。失败项提示原因，已成功处理的照片保留。
5. 点击缩略图进入大图查看；支持前后按钮、键盘方向键和水平滑动；首尾不循环，显示正确序号。
6. 点击「管理」后可前移、后移、设为封面或移除；使用显式按钮，不要求拖拽手势。移除仅影响草稿，保存后才更新原日记。
7. 第 9 张后不显示添加格，拍照禁用；批量选择超量时只处理剩余名额并提示。

## 6. 写作、草稿与阅读

- 新建和每篇编辑各有独立草稿键。文字、日期、照片顺序、心情和标签改变后，约 450ms 防抖保存到 IndexedDB。
- 显示「正在保存」「已保存」「已恢复」「保存失败」状态；路由离开前尝试提交草稿，失败时提醒保留内容。
- 浏览器关闭提示仅能在平台允许时显示；系统强制杀进程不能保证最后尚未提交的输入已经保存。
- 保存记录与删除对应草稿在同一事务中完成；编辑保留 ID 和创建时间，更新 `day` / `updatedAt`。
- 详情页默认只读；管理行为放在「更多」。删除需要二次确认；取消保留，确认后删除记录及对应编辑草稿，相册原图不变。
- 图片懒加载，应用复用并及时释放不再引用的 Object URL。

## 7. 存储与迁移

IndexedDB 数据库 `xinqing-journal` 版本 1：

| Store | 内容 |
|---|---|
| entries | id、title、note、mood、tags、day、date、updatedAt、photos |
| drafts | new / edit:ID 对应的独立图文草稿 |
| meta | 旧数据迁移标记、原始备份与异常标记 |

照片结构为 `{ id, blob, name, width, height }`。日记与 Blob 保存在同一条记录中，避免保存文字成功却丢照片；事务完成后才提示成功。

首次初始化迁移 `localStorage['xinqing.entries.v1']` 中有效旧记录，在同一事务内写入迁移标记；保留旧键与原始内容。之后读取 IndexedDB，避免重复迁入已经被删除的旧日记。旧关怀反馈继续保存在 `xinqing.care.v1`。

示例照片是内置生成素材，示例新增/修改/草稿仅保留在内存，不写入个人数据。桌面网页、手机网页、Android WebView 是独立存储环境，没有自动跨设备复制或实时多标签页合并。

## 8. 备份与恢复

入口：我的手帐 → 备份与恢复。只在个人模式显示。

- 格式：JSON，`format: xinqing-photo-journal`，`version: 1`，包含已保存日记和照片 Data URL 实际字节。
- 范围：不包含未保存草稿、关怀反馈或设置。导入/导出上限 100 MB；当前没有分卷导出。
- 网页导出：生成下载文件，提示检查下载位置。
- Android 导出：写入 App 缓存，再打开系统保存/分享窗口；用户选择的目标是否已保存需自行确认。
- 导入先检查结构、日期、图片格式和可解码性；显示篇数、照片数、新增数、跳过数后，再点击确认。
- 同 ID 已存在时保留本机记录，不覆盖、不按时间自动合并。不同 ID 即使内容相同也视为不同记录。
- 验证失败不写入任何记录；提交使用一个事务，失败则不提交本次变更。
- 备份是明文内容，不上传到项目服务器。跨端转移属于用户主动导出/传输/导入。

## 9. 与现有情绪功能联动

图文记录和原有快捷记录使用同一份记录集合。按记录日倒序，同日按创建时间倒序；七天趋势按 `day` 分组，仅平均 1–5 的有效自评。未选心情的照片日记不画作一般或低落。低落因素仅包含最近七天心情 1–2 的记录标签。

首页快捷记录依旧必须选心情，最多 500 字；图文编辑器的可选心情和 5,000 字规则不改变快捷入口。既有三张便签顺序、自然声图片同步、计时、暂停与反馈保持可用。

## 10. 验收与异常

| 场景 | 验收结果要求 |
|---|---|
| 旧 localStorage 日记首次打开 | 迁入新数据库，原始内容仍在 |
| 添加 3 张实际图片，刷新编辑页 | 文字、图片字节与顺序从草稿恢复 |
| 第 2 张设为封面后保存 | 卡片封面、详情与查看器顺序一致 |
| 保存未选心情的图文日记 | 可以保存，不改变当天情绪均值 |
| 编辑为 700 字并改为昨天 | ID 不变，正文和日期完整保留 |
| 刷新带 ID 的详情地址 | 等待数据库初始化后显示正确记录 |
| 模拟写入失败 | 留在编辑页，输入保留，无假成功 |
| 示例中创建日记 | 个人数据库条数不变 |
| 删除取消 / 确认 | 前者保留；后者仅删除目标记录 |
| 导出、删除一篇、恢复备份 | 恢复真实图片；同 ID 本机记录不覆盖 |
| 手机和电脑 | 320 / 390 / 430 / 640 / 768 / 960 / 1024 / 1440 / 1912px 逐篇不混排、预览无溢出 |
| 原有快捷记录与自然声 | 保存、刷新、声音切换、音量、暂停、计时通过回归 |

新增 `album-layout-browser-check.cjs` 对 1 / 2 / 3 / 9 图、纯文字、长标题、完整九图查看与筛选进行回归。

真实 Chromium 脚本：[album-browser-check.cjs](../tests/album-browser-check.cjs)、[care-browser-check.cjs](../tests/care-browser-check.cjs)。这些验证不代表已在 Android 真机上验证系统相机、文件选择、系统分享、软键盘或后台进程回收。

## 11. 本版不包含

云同步、账号体系、社交发布、地图定位、相册原图托管、图文富文本混排、无限照片、全文搜索、AI 看图识别心情、照片滤镜、回收站、应用商店发布均不在此次范围。

后续先验证真实手机记录与回看体验，再考虑稳定签名升级、原生存储、照片分卷备份与可选云同步。没有已验证的用户增长、留存或情绪改善结论。
